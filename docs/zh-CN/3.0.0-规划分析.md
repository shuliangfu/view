## 1. 结论先行

### 1.1 何时需要 3.0.0？

**只有在「故意破坏 2.x 兼容」时才升 major。**\
2.1.0 已把「加法型」能力（细粒度子路径、水合
`mismatchMode`、编译器静态提升等）落在 **minor**；3.0 留给 **减法 / 改默认 /
改签名**。

| 变更类型                               | 版本建议        |
| -------------------------------------- | --------------- |
| 新子路径、新可选参数、文档与内部优化   | **2.1.x / 2.2** |
| 主入口删 re-export、改默认行为、删 API | **3.0.0**       |
| 仅 bugfix / 安全 harden / 内部 perf    | **2.1.x patch** |

### 1.2 一句话目标

**3.0 = 默认路径更小、更可预测、更接近 Solid 系「编译优先 +
细粒度更新」的产品形态；**\
用一次清晰的迁移窗口，把 2.x 为兼容背着的「全家桶主入口」与历史语义收拾干净。

### 1.3 不做什么（刻意排除在 3.0 默认范围外）

- 不重写响应式内核订阅结构（除非 bench 证明链表是瓶颈）
- 不默认上时间分片 / React lanes 式可中断渲染
- 不把业务组件库（ui-view）塞进 view 核心
- 不在 3.0 同时做「包体大手术 + 调度器统一 +
  渐进水合产品化」全部堆一个大版本（应分期）

## 2. 2.x 现状与 3.0 的关系

### 2.1 2.1.0 已具备（3.0 的前置）

- **细粒度
  exports**：`/reactivity`、`/scheduler`、`/router`、`/form`、`/resource`、`/control-flow`、`/csr`，以及既有
  `/ssr`、`/compiler`、`/optimize`、`/portal`、`/jsx-runtime`
- **主入口仍是 convenience
  barrel**：`import { createSignal, createRouter } from "@dreamer/view"`
  仍拉全家桶（**利于兼容，不利于默认包体**）
- **水合诊断与策略**：`mismatchMode: continue | assert | remount`（默认
  continue）
- **For 键控 LIS、安全 props/URL、共享 escape** 等运行时质量已在 2.0.6–2.1.0
  落地
- **`sideEffects: false`** 已声明，但主入口 re-export
  仍限制「从主入口摇树」的收益

### 2.2 2.x 故意保留的「技术债 / 兼容债」

| 债                                     | 为何 2.x 保留 | 3.0 方向                      |
| -------------------------------------- | ------------- | ----------------------------- |
| 主入口 re-export router/form/store…    | 零迁移        | 主入口瘦身或改为「核心 only」 |
| 未编译路径偏「通用解释器」             | 编译器仍演进  | 编译默认更强；运行时减分支    |
| batch 与 priority 解耦                 | 架构级        | 可选 RFC，可不绑 3.0 必做     |
| 渐进水合 / 分片水合                    | 产品未就绪    | 2.2 演进或 3.0 可选特性       |
| 部分旧语义（如无 key 的 For 整表重建） | 文档约定      | 可更严默认 + lint             |

## 3. 3.0.0 目标架构（建议）

```text
                  ┌─────────────────────────────┐
应用按需导入 ───► │  子路径（唯一推荐默认）      │
                  │  /reactivity /csr /ssr      │
                  │  /router /form /control-flow│
                  └─────────────┬───────────────┘
                                │
                  ┌─────────────▼───────────────┐
                  │  主入口 @dreamer/view       │
                  │  3.0：仅「核心 CSR 内核」   │
                  │  或 明确「兼容别名包」策略  │
                  └─────────────────────────────┘
```

**推荐策略（二选一，发版前必须拍板）：**

| 策略                                 | 主入口内容                                                                   | 迁移成本          | 包体收益 |
| ------------------------------------ | ---------------------------------------------------------------------------- | ----------------- | -------- |
| **A. 激进瘦身（推荐作为 3.0 正主）** | 仅 signal/effect/owner/insert/mount·hydrate/控制流/Suspense 等与 `/csr` 接近 | 中：业务改 import | 高       |
| **B. 温和 barrel**                   | 主入口仍 re-export，但 **废弃一年** 后 3.1 再删；3.0 只改默认与少量签名      | 低                | 中       |

**规划默认建议：3.0 采用 A**，并在 2.x 用文档 + 可选 lint 预热；若 monorepo 内
dweb 等迁移压力大，可 **3.0 = B + deprecation，3.1 = A**。

## 4. 破坏性变更清单（候选）

下列为 **候选**，实施前需逐项打「进 3.0 / 延后 / 否决」标签。\
原则：**每条都必须写迁移说明**；无迁移路径的不进 3.0。

### 4.1 包体与导出（P0，3.0 核心）

| ID | 变更                                                                                                 | 破坏面                                  | 迁移                                              |
| -- | ---------------------------------------------------------------------------------------------------- | --------------------------------------- | ------------------------------------------------- |
| E1 | 主入口 **不再** re-export `createRouter` / `Link` / `createForm` / Resource（**已落地 2026-11-04**） | 所有从主入口引路由/表单/Resource 的代码 | 改为 `@dreamer/view/router`、`/form`、`/resource` |
| E2 | 主入口 **不再** 默认导出重型集成（以 E1 为准；**已落地**）                                           | 同上                                    | 同上                                              |
| E3 | 删除或改名过时子路径 / 内部 re-export 别名                                                           | 深路径依赖                              | 提供 codemod 表                                   |
| E4 | `exports` 中 **禁止** 未列出的 deep import（若当前有人深链 `src/...`）                               | 非公开路径用户                          | 只保证 exports 表                                 |

### 4.2 运行时语义（P1）

| ID | 变更                                                                                                                  | 破坏面                          | 迁移                              |
| -- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------- | --------------------------------- |
| R1 | `hydrate` 默认 `mismatchMode` 从 `continue` 改为 **`assert`（VIEW_DEV）/ `remount`（生产）**（**已落地 2026-11-04**） | 依赖「静默错位继续跑」的 hybrid | 显式传 `mismatchMode: "continue"` |
| R2 | 无 `key` 的 `For`：开发态 **警告** 或生产 **要求 key**（若产品决定）                                                  | 未写 key 的列表                 | 补 `key` 或改用 `Index`           |
| R3 | 删除已废弃布尔开关 `assertMismatch` / `remountOnMismatch`（**已落地**）                                               | 使用弃用字段的代码              | 改用 `mismatchMode`               |
| R4 | 事件委托 / 非冒泡事件白名单调整                                                                                       | 极端自定义事件名                | 对照迁移表                        |
| R5 | SSR 伪 DOM 与浏览器 DOM 行为差异收紧（更少「碰巧能用」的 API）                                                        | 在 SSR 上依赖完整 DOM 的代码    | 改为 CSR-only 或补齐文档边界      |

### 4.3 编译器与构建（P0–P1）

| ID | 变更                                                                      | 破坏面                         | 迁移                                |
| -- | ------------------------------------------------------------------------- | ------------------------------ | ----------------------------------- |
| C1 | **默认开启** 更强静态提升 / 更少 Effect 产物（可能改变更新粒度边界 case） | 依赖「多余 Effect 时序」的边角 | 测业务；提供 `compilerOptions` 回退 |
| C2 | 编译产物要求固定 runtime 辅助导入路径（如只从 `/csr` 或固定 symbol）      | 自拼 transform 流水线          | 对齐官方 esbuild/插件               |
| C3 | 移除未文档化的编译实验开关                                                | 实验用户                       | 见 CHANGELOG                        |

### 4.4 调度与异步（P2，可不进首发 3.0.0）

| ID | 变更                                   | 说明                                                            |
| -- | -------------------------------------- | --------------------------------------------------------------- |
| S1 | `batch` 与 `priority` **统一任务模型** | 架构级；建议 **独立 RFC**，可作为 3.0 的「可选 breaking」或 3.1 |
| S2 | `createDeferred` 默认优先级变化        | 需产品证据                                                      |
| S3 | Resource 默认支持 / 要求 `AbortSignal` | 加法可先 2.2；删除旧签名才 3.0                                  |

### 4.5 类型与公共类型（P1）

| ID | 变更                         | 说明                                                     |
| -- | ---------------------------- | -------------------------------------------------------- |
| T1 | 收紧 `any` / 宽泛 props 类型 | 可能 TS 编译失败（行为未必变）                           |
| T2 | 重命名内部曾导出的类型       | 提供 type alias 过渡一个 minor 再删（若放 2.x 过渡更好） |

### 4.6 明确 **不建议** 作为 3.0 必破的

- 改 Signal 的 `.value` / 调用式双形态（迁移面极大）
- 改 JSX 为非 Thunk 模型（等于新框架）
- 强制虚拟滚动进核心

## 5. 非破坏但仍建议与 3.0 同期交付的能力

这些可以是 **3.0 的「卖点」但不强制 break**，也可先落在 **2.2**：

| 能力                                                     | 价值     | 备注                         |
| -------------------------------------------------------- | -------- | ---------------------------- |
| 编译器：文本/属性 **直连 DOM 绑定**（少走通用 `insert`） | 性能上限 | 对齐 Solid                   |
| 水合：错位 **分片恢复**、更清晰的 assert 报告            | Hybrid   | 2.1 已有 remount/assert 基础 |
| 渐进水合 / 路由级 hydrate                                | 产品     | 与 dweb 黄金路径绑定         |
| DevTools：Owner / 订阅数（仅 VIEW_DEV）                  | DX       | 不进生产路径                 |
| 官方 codemod：主入口 → 子路径                            | 迁移     | **3.0 发布配套必做**         |
| 体积预算 CI：main vs `/csr` vs `/reactivity`             | 工程     | 防止回退                     |
| Form：checkbox/select/schema 桥                          | DX       | 可 2.2                       |

## 6. 主入口 3.0 建议导出面（策略 A 草案）

> 下列为讨论稿，落地以 `deno.json` `exports` + `src/mod.ts` 为准。

**建议保留在主入口（或与 `/csr` 对齐）：**

- 响应式：`createSignal`、`createEffect`、`createMemo`、`createRoot`、`onCleanup`、`untrack`、Context、Store（若
  Store 体积可接受；否则 Store 仅 `/reactivity`）
- 运行时：`mount`、`hydrate`、`insert`、`setProperty`/`spread`、`createRef`
- 控制流：`Show`、`For`、`Index`、`Switch`、`Match`、`ErrorBoundary`、`Portal`/`createPortal`
- 异步 UI：`Suspense`、`lazy`、`Dynamic`、`createResource`（Resource
  是否进主入口可再议）
- 调度：`batch`

**建议仅子路径：**

| 能力              | 子路径                             |
| ----------------- | ---------------------------------- |
| 路由              | `/router`                          |
| 表单              | `/form`                            |
| SSR               | `/ssr`（**禁止**进浏览器主入口图） |
| 编译器 / optimize | `/compiler`、`/optimize`           |
| CLI / setup       | `/cli`、`/setup`                   |

**迁移示例：**

```ts
// 2.x
import { createForm, createRouter, createSignal } from "@dreamer/view";

// 3.0（策略 A）
import { createSignal } from "@dreamer/view"; // 或 /csr /reactivity
import { createRouter } from "@dreamer/view/router";
import { createForm } from "@dreamer/view/form";
```

## 7. 迁移与发布策略

### 7.1 发布前（2.x 尾声，建议 2.2）

1. 文档默认示例 **全部改为子路径导入**（主入口仅出现在「便捷」小节）
2. monorepo 内 **dweb / examples** 先迁子路径（吃自家狗粮）
3. 提供可选 ESLint/自研 lint：`no-restricted-imports` 禁止从主入口引 router
4. CHANGELOG 写清「3.0 预告」与时间窗
5. 体积基线：记录 `2.1` 的 main / csr / reactivity 产物大小

### 7.2 3.0.0 发布检查清单

- [ ] 破坏项锁定表（本章 4.x 勾选进 3.0 的最终列表）
- [ ] 中英文 CHANGELOG + 迁移指南（`docs/zh-CN/MIGRATION-3.0.md` 可新建）
- [ ] codemod 或至少对照表 + 脚本
- [ ] Deno + Bun 全量测试；dweb hybrid 冒烟
- [ ] JSR `exports` dry-run；无 deep import 泄漏 `node:*` 到浏览器图
- [ ] 版本：`deno.json` / `package.json` = `3.0.0`，tag `v3.0.0`
- [ ] 下游：dweb 等显式升 `^3.0.0`（`^2` **不会**自动升）

### 7.3 版本节奏建议

```text
2.1.x     修 2.1 问题；文档推子路径
2.2.0     编译器/水合/Resource 等「加法」增强；3.0 预告 + 弃用注释
3.0.0     主入口瘦身 + 锁定的 breaking 语义 + 迁移工具
3.0.x     稳定与安全
3.1.0     调度统一 / 渐进水合等（若未塞进 3.0）
```

## 8. 风险与回滚

| 风险                       | 缓解                                                         |
| -------------------------- | ------------------------------------------------------------ |
| monorepo 多包同时爆红      | dweb 等先在 2.2 完成子路径迁移；3.0 日只改 view + 下游版本号 |
| 编译默认更强导致「时序」差 | 保留 `compilerOptions` 兼容档一个 minor                      |
| 用户大量复制旧 README      | 根 README 醒目迁移框；旧版本文档归档                         |
| 包体收益不及预期           | 发版前用 esbuild metafile 对比；不达标则缩小 E1 范围         |

**回滚：** major 不可「退回 2.1 当 3.0」；问题用 **3.0.1** 修。下游未升 major
的仍留在 2.1。

## 9. 成功标准（3.0 可称为成功）

1. **默认推荐路径**下，纯 CSR 计数器应用可只依赖 `/csr`
   或瘦身后的主入口，**不解析 router/ssr 图**
2. 官方 examples + dweb 主路径在 3.0 上 **全绿**
3. 迁移文档使「2.1 → 3.0」可在 **1 个工作日内**完成中等应用（有 codemod 更佳）
4. 无未文档化的 breaking；CHANGELOG 与本文最终锁定表一致
5. 安全基线不低于 2.1（URL / 事件 / HTML 策略不回退）
