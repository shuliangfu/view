## 1. 体积基线（view 源码 only）

工具与命令：

```bash
node scripts/size-baseline/measure.mjs --write
# 等价：deno task size:baseline
```

方法：esbuild bundle
ESM、`platform: neutral`、开启摇树；`@dreamer/*`／`happy-dom`／`typescript`
**external**，字节数只含本仓库 `src/`。gzip = 对 minify 产物 zlib level 9。

| entry                      |       raw |        minify |     gzip(min) | #src files |
| -------------------------- | --------: | ------------: | ------------: | ---------: |
| `@dreamer/view`（主入口）  | 98.81 KiB | **43.51 KiB** | **15.36 KiB** |         33 |
| `@dreamer/view/reactivity` | 24.00 KiB |     10.46 KiB |      3.85 KiB |         13 |
| `@dreamer/view/csr`        | 70.06 KiB |     30.04 KiB |     10.62 KiB |         28 |
| `@dreamer/view/ssr`        | 93.47 KiB |     44.45 KiB |     14.55 KiB |         25 |
| `@dreamer/view/router`     | 57.39 KiB |     25.97 KiB |      9.20 KiB |         24 |
| `@dreamer/view/form`       | 13.63 KiB |      5.88 KiB |      2.45 KiB |          8 |
| `@dreamer/view/resource`   | 13.94 KiB |      6.05 KiB |      2.36 KiB |         12 |

### 解读

- 主入口 minify ≈ **reactivity × 4.2**、gzip ≈ **× 4.0**。只需要 Signal／Effect
  的应用若从主 barrel 导入，默认多付约 **33 KiB minify／11.5 KiB gzip**。
- `csr` 已明显轻于主入口（无 router／form 全家桶），仍重于纯 `reactivity`。
- `router` 单独也有 ~26 KiB minify——路由场景应走 `/router`，勿为「只要一个
  Link」拖主入口。
- `form`／`resource` 本身很轻；从主入口拿它们仍会连带其它 re-export 图（取决于
  bundler 对 `export *` 的摇树能力；**实测全量 re-export 入口无法摇到 reactivity
  体积**）。

## 2. 性能基线（现有 `tests/bench/*`）

命令：`deno task bench`（详见 `bench-baseline.md`）。

摘要（avg）：

| 类      | 代表项                        | avg     |
| ------- | ----------------------------- | ------- |
| Signal  | 同值写跳过 ×1000              | 2.6 µs  |
| Effect  | 1 signal × 100 effect + batch | 13.2 µs |
| For+key | 创建 200 行                   | 1.6 ms  |
| For+key | 反转 200 行                   | 2.2 ms  |

结论：热路径量级健康；本刀**不**据此改内核。后续优化应用
**同命令对比本表**，禁止「感觉更快」。

### 如何测真实页 Effect／DOM 操作（未改核心）

核心**故意**不内置计数器（避免默认开销与 API 膨胀）。推荐：

1. Chrome Performance：对真实页（ui-view
   文档／dweb-admin）录制一次列表更新，对比 Scripting／Rendering。
2. 一次性本地探针：仅在脚本里包装 `createEffect`／统计 `insert`
   调用次数，**勿写入 `src/`**。
3. 若将来要正式计数，须另开刀：可选 debug 导出、默认关闭——不在 P0。

## 3. 下一步最值得做的 **一条** 2.x 非破坏优化

候选对比（本基线证据）：

| 候选                      | 证据是否已齐                            | 风险                 | 用户收益           |
| ------------------------- | --------------------------------------- | -------------------- | ------------------ |
| **文档强推子路径导入**    | ✅ 主入口 vs reactivity／csr 数字已量化 | 极低（纯文档／示例） | 立刻让应用少拖代码 |
| 体积 CI 门禁              | ✅ JSON 可作阈值                        | 低                   | 防回退，不直接变小 |
| Resource 可选 Abort／去重 | 分析有缺口，本刀无流量证据              | 低（可选参数）       | 路由切换取消请求   |
| 编译器 golden 小步        | 需另建 golden 夹具                      | 中（编译面）         | 少 Effect／可回滚  |

### 推荐（唯一一条）

**文档强推子路径导入：默认示例全部改为
`@dreamer/view/reactivity`／`/csr`／`/router`
等；主入口仅保留「便捷全家桶」小节。**

理由：

1. **本刀数字直接支撑**：主入口 gzip 15.36 KiB vs reactivity 3.85 KiB；子路径自
   2.1.0 已存在，缺的是「默认心智」而不是新 API。
2. **零破坏**：不改导出、不改运行时；与 3.0「删主入口
   re-export」衔接，却把收益提前到 2.x。
3. **比先做 CI
   门禁更赚**：门禁防回退，但用户包体不会自己变小；先改文档／examples／monorepo
   消费方，再用本 JSON 加 CI。

**明确不做（本推荐范围内）：** 推倒响应式内核、默认时间分片、虚拟列表进核心、JSR
发版。
